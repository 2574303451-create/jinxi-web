# UI-004 A · 浏览器性能与执行验证

这是本机实验室比较，不是线上真实用户数据，也不是对线上 LCP / INP / CLS 达标的声明。

## 条件与可复现步骤

- 同一电脑、Node 24.6.0、npm 11.5.1、独立系统 Edge 140；修改前固定于 `0182518277831ba0d03df3a3e1973f1a7ae06efe`，修改后为本检查点生产静态构建。
- 桌面 1440×1000，CPU 1×；手机 390×1000，CDP CPU 6×、网络延迟 150ms、下载 200000B/s、上传 93750B/s。CPU 降速相对于本机，不等同真实低端手机硬件。
- 同一份12条明确标注的合成留言通过本机真实 HTTP 返回，其他业务接口503，禁止写入。没有把 fixture 当真实 API 或数据库结果。
- 每种条件分别记录可见 / 离屏，各3次、每次7秒；每组第一次包含实际 Chrome Performance trace，后两次只取CDP累计指标差。录制时未并行运行构建或其他浏览器测试。
- 新版是两行、旧版是一行，且同时隔离了旧终端每秒父组件渲染。这些是比较混杂因素，不能把所有开销差异只归因于 transform。
- `node artifacts/ui-004-a/performance.cjs before|after`；预览地址可用 `PREVIEW_URL` 指定。基线须先在独立worktree生产构建；开发服务器会覆盖其out，不可用开发产物冒充生产基线。

原始数据：[修改前](before/performance.json)、[修改后](after/performance.json)。`before/` 与 `after/` 各有4个 `.trace.json.gz`，可导入 Chrome/Edge DevTools Performance。脚本保留每次采样与所有录制，没有只留最有利的结果。

## 整页加载与交互限制

| 本机样本 | LCP 前→后 | 全过程CLS 前→后 | Event Timing最大交互样本 前→后 |
| --- | --- | --- | --- |
| 桌面 | 3012→2332ms | 0.00413→0 | 80→88ms |
| CPU6×慢网手机 | 3696→3552ms | 0.00596→0.07419 | 56→96ms |

**慢手机LCP未达到2.5秒目标，不能宣称整页加载优化通过。** 最终桌面2332ms单次样本虽小于目标，但另一次后测为6560ms、慢手机7452ms，完整保存于[after-initial/performance.json](after-initial/performance.json)及同目录原始trace，未删除不利样本。两次后测之间还修复了原生IO批量事件状态问题，不能把两者当完全相同构建的重复抽样。

资源证据中，既有外部 `cdn.jsdelivr.net/.../remixicon.css` 前测桌面2731ms且传输0字节，初次后测5733ms、最终2075ms；初次后测手机约6571ms且传输0字节，最终约2734ms且传输0字节，并有连接失败记录。该渲染阻塞资源的成功/失败及耗时波动使加载不具备严格一致的网络条件。首页布局与外部图标加载代码未改，本次只报告实际结果和混杂因素，不断言它是唯一原因，也不从单次样本推算长期回归幅度。最终慢手机全过程CLS比基线增大但小于0.1；没有采集足够的元素归因数据证明其具体来源，不宣称无布局偏移。后续需独立处理现有图标加载与首屏资源，然后多次控制变量复测。

Event Timing仅有少量实验交互；上述最大值**不是INP**，不能证明线上INP≤200ms。桌面长任务数1→3、慢手机9→8，包含加载、录制和交互的整个观察窗口，不能据此宣称无长任务。两侧均无未捕获pageerror；控制台存在预期503和外部图标资源错误，不记作“控制台全无错误”。初始加载CLS均为0，表中含后续交互全过程。

本地档案查询（键盘回车到结果可观察，含自动化开销）桌面827→90ms、慢手机920→105ms。新版删除了原500ms人为延迟；这不是服务器响应时延。

## 计时组件执行次数

另在真实开发浏览器用V8 precise coverage记录每种状态6.1秒。开发StrictMode可能双调用，不能把次数当生产耗时。原始记录：[前](render-counts-before.json)、[后](render-counts-after.json)，脚本 `render-counts.cjs`。

| 状态 | 旧GuildUptimeTerminal | 新父组件 | 新GuildRuntimeClock |
| --- | ---: | ---: | ---: |
| 收起且可见 | 12 | 无周期调用记录 | 6.1秒内无调用（分钟更新） |
| 展开且公会时钟可见 | 12 | 无周期调用记录 | 12 |
| 展开但整块离屏 | 12 | 无周期调用记录 | 无调用记录 |

这证明原每秒整块父渲染已隔离到可见的时钟叶组件。成员时钟另有自身可见性判断。查询提示status不随秒数变化，timer明确aria-live=off；真实读屏软件尚未人工测试。

## 原生后台与循环测量

[background-results.json](background-results.json)：独立有界面Edge实际切换标签页，主页面 `visibilityState=hidden` 时双行running=false、活动动画0，公会时钟ticking=false且文本冻结，切回前台恢复。

早期尝试普通Playwright上下文时，两标签都被强制保持visible，不能作为后台证据。最终使用独立自有浏览器，通过 `connectOverCDP(...,{noDefaults:true})` 保留原生可见性行为；未改写document.hidden或伪造事件。脚本关闭其自有窗口，不连接用户原有会话。

四宽度的真实transform位移、周期两侧可见卡片ID和位置，见[browser-results.json](browser-results.json)。桌面/平板循环距离1956px、时长61125ms，手机1776px、55500ms（12条合成样本均分每行6条）；固定速度32px/s。卡片变化会重新测量。原站28秒只作为已取证结构参考，不机械复制。
