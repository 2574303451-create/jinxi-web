# B2-0 检查点2：身份、积分与内容安全整改方案

基线：6abd039e898b9970d8d2ec4e7092e3e5b8f3aaf0（检查点1），上游PR9→PR8。先读ENVIRONMENT_AND_ENDPOINTS.md、OFFICIAL_RESEARCH.md及catalog-before.json。本文件是正式接入方案，不能当作已完成生产迁移或安全验收。下一检查点只在本机合成账号演示。

## 风险与当前处置

- **P0环境/凭据**：13入口已统一策略，旧身份/写接口暂停，5个公开GET只读且验证实际DB身份/权限。不能证明Netlify继承及真实PROD权限，云写入保持阻断。
- **P0身份**：旧localStorage、client account/userId、昵称与employee_no不建立服务器主体。旧登录仅PBKDF2校验无会话，跨域*、账户枚举、原始错误、无持久限流/会话撤销已通过暂停旧入口阻断；安全替代先在synthetic-local测试。
- **P0积分**：旧API接受奖励及兑换价格；不能因pointDelta≤5000就认为安全。旧SQL已有余额CHECK、FOR UPDATE、biz_id唯一索引，不能声称完全无并发/余额防护；但point_award仍可选客户端requested_delta，兑换接受客户端cost，business key亦由客户端选择。库约束不补足主体/规则/价格信任。
- **P0/P1内容**：旧匿名署名/反应身份、自报userId、共享管理口令、JSONB读改写丢更新、原始错误/日志已阻断或移除。历史游客不按昵称认领，新member_id只由服务器产生。游客写入暂不开放；是否恢复必须连同滥用、审核和隐私规则单独批准。
- **P0正式会话上线前**：现公告HTML清洗是客户端黑名单，且CSP允许unsafe-inline/unsafe-eval；尚未做全面HTML/URL语法、编辑器粘贴及存储型XSS验证。未来正式登录不能仅因HttpOnly就忽略同源脚本发起操作；先实施维护中的白名单清洗/安全渲染与可实现的CSP策略，再开放社区写能力。本机原型不读取真实内容。

## 可信主体和会话

以guild_member_accounts.id作为内部账号，profiles.employee_no仍是内部历史关联；新增稳定member_id/不透明公开UUID用于展示/作者外键，不直接公开工号或账号。实际授权测试库没有这两表；本机b2_lab将用同名合成表和明确synthetic source检查。正式表结构、迁移历史、唯一性、成员停用覆盖未知，不执行仓库含示例INSERT的历史DDL。

令牌为服务器32字节CSPRNG，不透明、只经__Host-前缀HttpOnly/Secure/SameSite=Lax/Path=/ Cookie。数据库只留SHA256令牌摘要；CSRF由服务器密钥绑定该令牌派生并只存摘要，原始CSRF只在同源响应及浏览器内存，不入URL/日志/localStorage。Cookie与CSRF不作为公开成员ID。

每次校验账号锁定、profile active/source、auth_version、撤销、绝对和空闲过期。改密事务更新hash/auth_version并撤销全部旧会话，清Cookie后要求重新登录；锁定/停用检查即时使旧会话无效，不依赖定时清理。退出撤销当前会话，多设备其他有效会话不误删。首次登录强制改密时仅me/改密/退出可用，禁止积分或资料写。多标签共享本设备Cookie/CSRF派生值，不靠localStorage回退。

起始本机测试策略为30分钟空闲/7天绝对，不是正式产品已批准期限。me恢复失败区分401与网络错误；只清私有状态，保留非敏感草稿。未知账号、错密码、锁定和停用统一错误；强制改密标志仅在密码验证成功后返回。密码hash格式严格校验、迭代和长度有界，异步PBKDF2；新hash采用当前官方建议的600k SHA256迭代，旧200k只作兼容测试。未验证生产hash分布或真实账户数据。

Origin精确同源、JSON Content-Type、绑定会话CSRF头、Fetch Metadata纵深校验；不采用CORS*与凭据。敏感操作必须重新校验当前会话状态。登录IP和账号桶使用服务器密钥摘要、持久原子计数/窗口，不能信任客户端X-Forwarded-For或单Function内存。日志不记密码、会话、CSRF、原图或原始IP。

## 积分安全替代

正式API只接收业务动作及受控商品code/幂等request id，不接收账号、memberId、增量、价格或任意rule。服务器从会话确定主体，活动完成事实由服务器可验证事件决定。不能允许“我完成了任务”的任意客户端声明兑换奖励。

原型只实现真实服务器日期签到：规则存在受限只读规则表，固定lab.checkin奖励；业务key由服务器成员+规则+UTC日期生成，重复/多标签/多设备只记一次。原型UTC日是测试口径，正式公会结算时区待业务确认。复杂任务/真实奖品均不启用。

兑换价格从可信商品表读取，客户端仅提交SKU与UUID request id；事务锁账户，检查既有收据→读取有效规则/商品→检查余额→唯一流水→余额更新→收据原子提交。余额CHECK>=0、流水唯一(member,server-biz-key)，同一幂等key跨动作冲突拒绝；不能只靠HTTP成功回执防重。不同账号的请求ID或资源不能访问其他人余额/台账，服务器不接受主体覆盖字段。

必须测试：无会话/伪localStorage/篡改主体/奖励/价格/失效CSRF/跨站、同日重复/并发签到、重复兑换/并发余额不足、超时重试、相同key不同SKU、改密/停用后旧会话重放。数据库/网络错误不返回成功、不泄漏SQL，客户端不把失败显示为0余额。

## 内容、游客和管理

成员写入必须由服务器会话给member_id、昵称及公开作者投影；游客明确kind=guest、无member_id/成员徽章，默认文字头像，不以同名绑定。暂不启用匿名投稿、回复或反应；未来恢复需请求/内容大小限额、同源/CSRF或游客独立防滥用、频率和审核策略。历史匿名内容外键为空。

管理员使用服务器角色/权限、近期验证及审计，弃用共享口令。公开列表不返回账号/反应用户数组/会话。原积分排行投影需先改为不透明公开ID和批准的公开字段，旧投影仍暂停。JSONB评论/反应写入改事务原子操作，不能拿整段数组覆盖并发更新。

## 头像与B2-C+准备（不执行）

正式头像先比较独立授权资源：Blobs site-wide跨部署共享，名称不同不是隔离；deploy store跟随部署清理，不能当持久唯一存储。独立TEST/PROD bucket及只限指定bucket的凭据是更明确的候选，但本轮未创建/读取存储配置。后续JPEG/PNG/WebP须服务器解码/重编码/去元数据/像素与频率限制；新对象可用后CAS替换指针，失败保留旧头像；所有原42/30/30px框不变。

B2-C+详见B2C_PLUS_PLAN.md：游客只看总数；名单仅认证成员读取、个人公开开关默认关闭，稳定成员ID去重并由服务端筛选。当前不建心跳、租约、名单API、隐私开关表或抽屉，不让合成伙伴冒充真实在线。
