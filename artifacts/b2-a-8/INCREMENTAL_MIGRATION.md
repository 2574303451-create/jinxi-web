# 旧账号导入退役与无损迁移计划

## 旧脚本风险

| 位置 | 源码行为 | 对历史数据的影响 |
| --- | --- | --- |
| `scripts/import_accounts_to_db.js:307–319` | 从输入接受散列或初始密码，解析首次改密标记 | 用旧文件重跑可让现有密码与账号安全状态被替换 |
| `:401–422` | 使用环境中的 `DATABASE_URL`，关闭 TLS 证书校验。默认执行 schema，之后才开始数据事务 | 目标身份缺少独立校验，事务回滚无法撤销此前执行的 schema |
| `:429–451` | 工号冲突时更新资料并设置 `is_active = TRUE` | 可重新启用原来停用的成员，并覆盖原有资料 |
| `:472–485` | 工号冲突时替换登录名、密码散列和首登标记，并设置 `is_locked = FALSE` | 可重置真实账户并解锁已经锁定的成员 |
| `:498–515` | 可同步旧签到记录及汇总表的署名 | 历史署名和业务含义会变更 |
| `:543` | 当前直接调用发布拒绝脚本，旧 `run()` 无入口 | 保留冻结。未来独立 TEST 候选解除构建拒绝前，另行验证旧导入仍有永久拒绝路径，避免把导入命令绑到发布入口 |

`--skip-schema` 只跳过 schema，数据覆盖仍在。旧脚本和历史 SQL 仅作审计证据。独立增量程序需要先在批准的合成数据上通过下表不变性验证。 [冻结回归](../../tests/freeze-release.test.cjs) · [历史表清单](HISTORICAL_DATA.md)

## 独立增量程序设计

1. **核验**。管理员先确认旧部署与实库归属，提供脱敏目录、键、约束、迁移版本和批准恢复编号。固定源、目标、用途、实际库指纹、schema 指纹、执行角色、部署 SHA 和允许操作。备份与实际隔离恢复通过后才制定迁移 SQL。
2. **生成计划**。新程序默认只读 `plan`，连接来自审批确定的独立配置，使用验证过的 TLS。先证明源只读、目标分类和角色符合批准范围。按现存稳定主键匹配，输出总数、键覆盖、重复、孤立、身份歧义与差异类别。批准前不得把私有行或凭据送出受控环境。未知 schema、约束或散列格式直接停止。
3. **旁表迁移**。先在专用 schema 建可版本化的账户映射、兼容视图和应用安全状态。映射使用管理员核实的源 `account_id`、档案主键和稳定成员 UUID。源行列出保留字段，首批对历史表无 UPDATE、DELETE 或 DDL 权限。相同来源/键和完全一致的旁表映射可安全重放；同键不同内容、无映射和多候选冲突进入人工队列。原来被锁定、停用或要求改密的状态继续生效。
4. **应用与核对**。将批准的计划散列、变更编号、目标指纹与实际 schema 绑定。事务内加迁移锁、再次核验范围、写入旁表并验证约束。先锁定业务写入窗口并排空已提交交易，读取同一快照的计数和对账证据。应用后的原表逐键比较必须零差异。用于私有比对的内容摘要只存受控环境，对外只发布一致性汇总。
5. **分批启用**。先以只读影子路径验证，再依次批准本人会话、作者、签到和积分。切换前后保留旧连接、发布 SHA、恢复点和写入流水水位。失败先冻结新写，撤销会话和角色，回退应用路由或视图。新路径若已接受交易，先对账并保存新增数据，再评审补偿。旧数据库和已接受记录保留。

首个可写候选、真实 TEST 联调及生产切换分别审批。当前交付停在程序规格和测试计划。真实表结构、源数据、角色与事务水位均未验证。 [管理员门槛](TEST_RESOURCES.md) · [备份与切换](BACKUP_RESTORE.md)

## 无损回归验收表

| 合成试验 | 通过证据 |
| --- | --- |
| 已存在且已改密的账号、锁定账号、停用档案与首登账号 | 旧表主键集合和每行字段完全一致，含密码散列、散列算法、首登、最后登录、锁定和停用。账号冲突不静默覆盖 |
| 同名用户、重复工号、孤立账号与缺映射档案 | 冲突导致停止或明确隔离，旁表完整唯一。昵称和 208 份公开档案不会成为账号映射依据 |
| 重放同一计划、两个迁移进程、事务中途失败 | 无重复映射，互斥可证，失败事务无部分写入。换目标或过期计划拒绝 |
| 无权限、错项目、错库指纹、错角色、schema 漂移 | 任一负例在写入前拒绝，日志只有失败分类和审批记录 |
| 留言、嵌套回复、攻略状态和附件历史 | 原主键、时间、署名和原始 JSONB 保持一致。可读正文及匿名归属复测 |
| 签到历史、补签、排行榜、积分及兑换 | 逐账户核对余额、流水顺序、业务唯一键、前后余额、兑换状态和历史差异。禁止通过重发奖励消除差异 |
| 序列、FK、触发器及默认 ACL | 恢复后可生成无冲突新 ID。权限、所有者和计划预期相符。未授权角色无原表写权限 |
| 切换窗口并发写和回滚 | 已提交写入完整保留，未提交及未确认请求可重试，新增合法订单有处理记录，旧部署可按审批回退 |

这组验收使用授权的合成账户和专用隔离库。私有恢复复验另行批准，真实数据与凭据不会进入 GitHub 或公开 TEST。
