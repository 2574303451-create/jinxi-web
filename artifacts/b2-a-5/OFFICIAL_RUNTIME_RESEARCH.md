## Netlify 构建与 Functions

- **构建机。** Netlify 支持通过 `NODE_VERSION`、`.node-version` 或 `.nvmrc` 指定 Node 24 的精确补丁版。选择顺序依次是 `.nvmrc`、`.node-version`、`NODE_VERSION`、站点 UI 的依赖设置。PR 13 的 `netlify.toml` 设置 `NODE_VERSION = "20"`、`NPM_VERSION = "10"`，CI 另测 20.20.2 与 24.22.1。Node 24.22.2 官方 ZIP 自带 npm 11.19.1，Netlify 的 `NPM_VERSION` 可以覆盖。保留 npm 10 主线时，npm 10.9.10 的引擎接受 24.22.2。实际验证应记录 Node 与 npm 的精确版本。 [Netlify 构建工具及优先级](https://docs.netlify.com/build/configure-builds/available-software-at-build-time/) · [Netlify npm 选择](https://docs.netlify.com/build/configure-builds/manage-dependencies/#npm) · [Node 下载归档](https://nodejs.org/en/download/archive/v24.22.2) · [npm 10.9.10 元数据](https://registry.npmjs.org/npm/10.9.10)
- **安装范围。** 基线的 Netlify 命令是 `npm ci && npm run build`，同一配置设置 `NODE_ENV = "production"`。npm 在这种环境下默认省略 devDependencies，基线的 Tailwind 和 PostCSS 工具链在 devDependencies。复现云端配置需覆盖这一差异。`npm ci --include=dev` 可以显式安装构建工具。若使用 `NPM_FLAGS`，它控制 Netlify 预先执行的 `npm install`，构建命令中的 `npm ci` 有自己的参数。 [Netlify 依赖安装规则](https://docs.netlify.com/build/configure-builds/manage-dependencies/#nodejs-environment) · [npm ci 的 omit/include](https://docs.npmjs.com/cli/v10/commands/npm-ci/#omit)
- **静态托管。** Netlify 为识别到的 Next 应用提供 OpenNext 适配器。该仓库以 `out` 发布静态文件，Functions 由自身入口提供。实际 TEST 需要核对生效的 publish 目录、适配器设置、404/file shadowing、`_headers` 和发布后 HTML 字节。若需跳过 SSR 适配器，当前适配器源码支持 `NETLIFY_NEXT_PLUGIN_SKIP=true`。 [Netlify Next 支持说明](https://docs.netlify.com/build/frameworks/framework-setup-guides/nextjs/overview/#how-netlify-runs-your-nextjs-app) · [适配器 skip 实现](https://github.com/opennextjs/opennextjs-netlify/blob/main/src/index.ts) · [Netlify 自定义响应头](https://docs.netlify.com/manage/routing/headers/)
- **托管 Functions runtime。** 构建 Node 的主版本符合有效 AWS Lambda runtime，且距离弃用超过两个月时，Netlify 默认据此选择 Functions runtime。当前文档的回退为 Node 24。可在 Netlify UI、CLI 或 API 配置 `AWS_LAMBDA_JS_RUNTIME=nodejs24.x`，重新部署后生效。`netlify.toml` 里的 `NODE_VERSION` 作用于构建，运行时覆盖使用平台环境变量。Lambda `nodejs24.x` 基于 Amazon Linux 2023，官方弃用日期是 2028-04-30，补丁由平台管理。 [Netlify runtime 规则](https://docs.netlify.com/build/functions/configuration/#nodejs-version-for-runtime) · [AWS runtime 表](https://docs.aws.amazon.com/lambda/latest/dg/lambda-runtimes.html#runtimes-supported)
- **本地打包与调用。** PR 13 锁定的 Netlify CLI 23.2.1 使用 `@netlify/zip-it-and-ship-it@14.1.4`。该版本的 runtime 映射止于 `nodejs22.x`，遇到 `nodejs24.x` 会交给平台选择。esbuild 的目标表也止于 Node 22，传入 24 时取默认 `node22`。因此应分别记录本机 Node、打包目标和最终托管 runtime。AWS Node 24 移除了 callback 型 handler，默认禁用 `require(esm)` 和自动模块识别。基线 Functions 使用 CJS 和 async 包装器，仍需验证最终打包产物及调用。 [锁定 CLI 元数据](https://registry.npmjs.org/netlify-cli/23.2.1) · [固定 bundler runtime 源码](https://github.com/netlify/build/blob/5fe77df7b4aed960ac5a29358d46f50600721d84/packages/zip-it-and-ship-it/src/runtimes/node/utils/node_runtime.ts) · [固定 esbuild target 源码](https://github.com/netlify/build/blob/5fe77df7b4aed960ac5a29358d46f50600721d84/packages/zip-it-and-ship-it/src/runtimes/node/bundlers/esbuild/bundler_target.ts) · [AWS Node 24 变更](https://aws.amazon.com/blogs/compute/node-js-24-runtime-now-available-in-aws-lambda/)

## TEST 隔离与变量元数据

公开 Netlify OpenAPI 的 `getEnvVars` 和 `getSiteEnvVars` 支持 context/scope 等筛选，返回的 `envVar` 含 `values`。CLI `env:list` 也会获取值，再按输出模式处理。公开接口尚无经核实的纯元数据投影，终端掩码或响应后过滤只能约束展示。Secrets Controller 的遮罩取决于 secret 标记和 deploy context，`dev` 中的 secret 值可读。当前证据限于公开合同，真实站点的 key、context、scope、site/team 来源仍待符合权限边界的独立证明。 [Netlify OpenAPI 固定版本](https://github.com/netlify/open-api/blob/96b688490fa406c71e4453e041ec5a0587d35f0b/swagger.yml) · [CLI 读取行为](https://docs.netlify.com/api-and-cli-guides/cli-guides/get-started-with-cli/#get-environment-variables) · [Secrets Controller](https://docs.netlify.com/build/environment-variables/secrets-controller/)

Netlify 默认变量可跨全部 context 和 scope，正式 TEST 需要独立证明环境变量的来源、凭据权限和资源边界。同站点的 Netlify Blobs `getStore` 跨全部 deploy context 持久共享，`getDeployStore` 提供按 deploy 划分的命名空间。数据库和长期媒体存储的 TEST 隔离应由服务端授权证据确认。当前实验的本地构建、合成数据和接口验证可作为后续 TEST 的输入，实际托管和资源权限仍待验证。 [Netlify 变量默认范围](https://docs.netlify.com/build/environment-variables/overview/) · [Netlify Blobs store 范围](https://docs.netlify.com/build/data-and-storage/netlify-blobs/#getstore)
