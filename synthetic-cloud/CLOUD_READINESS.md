将业务提交确认基线 `dbd6a3b24482872aaa1800b1e67236410062f1ae` 与真实 Gate-only 已验收修正 `bf1af47e576465bb230f56971cb45d2d89fe5261` 整合到独立审核分支。修复完整业务链路中同类的站点元数据拒绝，使已批准的 HTTPS 入口可以在提供方站点元数据为规范 HTTP 字符串时正常工作。

## 范围与验收

1. 完整业务的 Edge、Functions 调用门禁和会话服务桥接采用一致的精确元数据匹配规则：仅允许已批准 HTTPS 站点字符串及其同主机、无附加内容的 HTTP 字符串。不做 URL 归一化；路径、端口、用户信息、查询、片段、别名及其他主机拒绝。
2. 实际请求 origin、构建和运行时 `URL` 仍须精确为已批准 HTTPS；团队、站点、部署、提交、到期、访客凭证、客户端地址、业务身份、CSRF 与数据库门禁保持原有检查。
3. 先复现 Edge 与 Functions 拒绝，再修复；打包 HTTPS 演练及 Firefox 共享夹具使用 HTTP 站点元数据，构建、请求和运行时 URL 保持 HTTPS。验证真实临时 PostgreSQL 上的登录、会话和既有业务操作、隔离与回滚行为。
4. 保留合并后的完整 CI：业务与历史兼容、PostgreSQL、HTTPS、Firefox、原始类型检查、构建、导出隔离和工程检查；补入已验收 Gate-only 的诊断及 URL 用例。最终候选按业务基线做 Standards / Spec 增量审查，推送独立审核分支后核对同 SHA 的实际 CI。
