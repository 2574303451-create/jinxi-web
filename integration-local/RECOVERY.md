# 未确认操作的跨刷新恢复契约

当前本地统一网站实际启用IndexedDB数据库`jinxi-operation-receipts-v1`，与服务端Cookie身份配合；不向正式静态站导出此功能。不更改原幂等表、账本或事务权限，不保存密码、Cookie/CSRF、私有正文、交易金额或服务器响应。

1. 当前成员经过服务端核验后，按UUID＋业务模块＋请求正文SHA-256摘要取得原请求编号。签到摘要额外使用服务端返回的业务日期区分新一天，POST依旧不接受客户端日期。
2. IndexedDB读写事务原子地get/add；发送前必须完成落盘。存储被禁用、损坏、额度满或事务失败均停止写请求。多个标签、整页重载、关闭并重开浏览器用同一数据库取得同一编号。
3. 网络/5xx/408、无效或过时响应保留未知编号；随后401/403/429不能证明原请求失败。第一次新编号得到确定4xx时记录rejected，区别于unknown；修正正文产生新摘要，原服务器事务不会被客户端声明改写。
4. 同一成员重新登录后按稳定顺序分页核对本人回执，每页16条；前页未知记录不妨碍翻到后页。四个业务处理器在原会话、权限、资源/RLS、锁等待后及提交前重验范围内读取原幂等记录；仅返回请求号与committed/unresolved，不返回原私有内容。没有记录或社区回执未完成仍是unresolved，不自动重新执行或宣称失败。等待持久化确认之后也必须再次检查身份世代，旧结果不能返回给后来登录的人。
5. 已确认的编号继续保留，重复表单原样重试会得到原结果。只有用户明确点“确认已完成，允许新操作”且当前服务端再次证明提交后才移除，避免不知情地重复留言、扣减或退款。确需另一次相同内容时，应显式确认旧操作后开始新的意图。

仅列举的目标状态操作（排行公开、规则/商品启停、反应、加入/退出成员关系）在上一次已确认后允许新的设定意图，以支持true→false→true及加入→退出→再次加入；其未知结果仍保留原号。成员关系仍由原唯一活动成员/容量约束保证，不产生积分或其他外部奖励。这个分支不适用于创建、结算、扣减、退款或冲正，也不改变任何服务器权限或幂等约束。服务端确认回执后只释放同一编号的内存容量，未确认条目不能因清理额度被删除。

改变同类目标前先查询既有未知回执：服务器证明已提交才确认，仍找不到结果则拒绝相反目标；同值重试保留原号。IndexedDB的同一个读写事务还会再次检查并发标签插入的未知同类意图，避免两个标签各自通过早期检查后交错发布。此检查按操作种类保守串行，加入/退出属于同一成员关系种类；不以本机时间顺序猜测服务器交易结果。

**期限及隐私**：未知记录7天后停止自动重试，保留原标识等待核对，不能到期删除后盲目换号。第一次确定拒绝的rejected记录不等同未知，过期仍可沿用同一原号重试；任何已有未知结果后的401/403/429均不能将它降为rejected。当前成员可以主动清理30天前、且服务端再次确认的旧标识；没有后台自动删除。每次最多处理16条，可继续翻页而无需删除未知项；每origin最多512条，当前会话内最多128个未确认内存标识，满额安全拒绝。清理后的已确认意图或手动移除标识允许新请求，不能承诺无限期恰好一次。

本机UUID、操作类型及摘要仍是个人相关元数据，拥有该浏览器配置的本机用户/同源脚本能查看；它们不是登录或管理凭据。账号切换不向新成员展示旧成员标识，服务器也不接受客户端自报主体。不得在共用或不可信设备上把本机存储当作保密保险箱。

网站数据被手动清空、浏览器隐私模式不保留数据、设备损坏/跨设备或存储被恶意篡改不属于“同一持久存储正常保留”的保证。此时必须先查看本人事实/订单/流水并人工确认，不得盲重做；未来云启用前应验收更长周期的服务器查询/对账与备份策略。服务器原幂等记录目前未设自动删除，未来清理也须独立对账及审查。

没有读取真实历史成员或改变云端行为。本轮实际故障注入、服务端数据和浏览器关闭重开证据见artifacts/phase4-adaptation，不把模拟传输丢包描述为自然生产事故。
