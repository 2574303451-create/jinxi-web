## 授权后的运行边界

| 用途 | 资源与运行身份 | 放行标准 |
| --- | --- | --- |
| 原站继续运行 | 现有部署和原连接，待确认 `jinxi-web` 归属 | 保持历史连接，先证明备份和回滚。空库、未知旧项目、同项目子分支均不得当作新旧资源互换 |
| TEST 只读 Functions | 独立 Netlify TEST 站点和 `jinxi-test` 的专用合成读取角色 | 使用实际 `branch-deploy` 或 `deploy-preview`。独立站点默认分支也可能使用 Netlify `production` context，应调整部署方式。角色匹配 `synthetic-test` 和库指纹，站点无法获取生产密钥 |
| TEST 后续写入验证 | `jinxi-test` 独立、可回滚、权限受限的合成环境 | 只在 F08 批准范围执行，管理角色与运行角色分开，旧写接口仍关闭。拒绝路径在隔离副本验证，生产权限仅用管理员证据 |
| 私有恢复演练 | 与 TEST 及站点都分离的受控 PG17 环境 | 真实归档仅在另行获批的隔离工作区恢复，必要权限限时并登记销毁。公开 TEST 只接合成数据 |

实际网络、身份、角色和隔离需要 T01–T09 证据。`JINXI_CLOUD_ISOLATION_APPROVAL` 仅记录完成的审批。保留当前 Git 发布冻结，管理员先完成 F01–F08，再单独评审 TEST 候选。 [托管验收步骤](../b2-a-7/TEST_SIGNOFF.md#取得-f08-授权后执行) · [数据保护与恢复](BACKUP_RESTORE.md)
